# chwicklund

Source for [chwicklund.com](https://chwicklund.com), the personal site of Charles Wicklund: a single-page portfolio with projects, an about section, a contact form that opens your email app, and a gallery of photographs he took. It is a React + Vite app with no backend, built and published to GitHub Pages by a GitHub Action.

The site links out to other projects rather than hosting them. For example, [Hoops Predictor](https://basketball.chwicklund.com/game) lives in its own repository and is deployed separately.

## Layout

```
src/content/site.json   every word on the site (see below)
src/content/images.json image sizes, written by `npm run images`
src/components/         one component per section: Hero, Projects, Photos, About, Contact, Footer, plus Stage
src/palettes.css        colours, generated by scripts/build-palettes.py
photos/                 full-size originals of the photographs
public/                 web-sized images, project screenshots, og.jpg and the CNAME
scripts/                image optimiser and palette builder
.github/workflows/      the deploy to GitHub Pages
```

## Editing the site

**Every word on the site lives in [`src/content/site.json`](src/content/site.json).** Change it, save, and the dev server updates.

- `hero.photo` — the photograph beside the first screen; `hero.photoAlt` describes it for screen readers.
- `projects.items` — one entry per project. `stage` is what shows in the fixed half beside it:
  - `{ "kind": "shot", "src": "/img/projects/…webp", "width", "height", "alt" }` for a screenshot
  - `{ "kind": "code", "code": "…" }` for a code fragment
  - `{ "kind": "table", "rows": [["label", "value"], …] }` for a settings table
  - `{ "kind": "self" }` shows this site's own JSON
- `photos.items` — the drag row, in order. Portrait photos become tall frames; landscapes pair up or run wide.
- `stages` — the photographs beside About and Contact, each with `photo` and `alt`.
- `footer.photo` — the close-up beside the footer menu; `footer.photoFocus` is the point it zooms in on (`"x% y%"`).

## Colours

The palette (Rose) is set in [`scripts/build-palettes.py`](scripts/build-palettes.py). Change a colour there and run `python3 scripts/build-palettes.py`: it checks that the cream text still reads on every ground and rewrites `src/palettes.css`.

## Adding a photograph

1. Put the full-size original in `photos/` (keep the file name: it is how the JSON refers to it).
2. Run `npm run images`. This writes web-sized copies to `public/img/` and their sizes to `src/content/images.json`.
3. Add `{ "file": "<name without extension>", "alt": "…" }` to `photos.items` in `site.json`.

## Commands

- `npm install`, then `npm run dev` for local development
- `npm run build` outputs to `dist/` (with a `404.html` copy, so old links like `/photos.html` still land on the right section)
- `npm run images` after adding or replacing a photo (also rebuilds the link-preview image `public/og.jpg`)

## Deploying

Pushing to `master` builds and publishes the site through [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml).

One-time switch: the repo's Pages used to publish the `master` branch as-is. In **Settings → Pages → Build and deployment**, set **Source** to **GitHub Actions** (or run `gh api -X PUT repos/chwicklund/chwicklund/pages -f build_type=workflow`). The custom domain and HTTPS certificate stay as they are.
